🔒 Payment Verification Security Test Suite

Task 11.4: Test payment verification security
Requirements: 6.1, 6.2, 6.5

⚠️ Security Testing Warning: These tests verify that the payment system correctly rejects invalid payments. Some tests require backend access or API testing tools. DO NOT attempt to bypass security measures in production.
Testing Approach: These tests verify the backend payment verification logic. You'll need to use API testing tools (like Postman or curl) to send requests directly to the backend API with manipulated data.

Test 1: Incorrect Payment Amount

Test Case 1.1: Payment Less Than 1 SOL

Steps:
  1. Create a transaction sending 0.5 SOL to treasury
  2. Get the transaction signature
  3. Try to submit card with this transaction signature via API: 
    POST /api/cards/submit
{
  "cardData": { ... },
  "transactionSignature": "SIGNATURE_HERE",
  "walletAddress": "YOUR_WALLET"
}
Expected Result:
✓ API returns 400 Bad Request
✓ Error message: "Invalid payment amount. Expected 1 SOL, received 0.5 SOL"
✓ Card is NOT published
✓ Transaction signature NOT stored in database
✓ Backend logs the rejection

Test Case 1.2: Payment More Than 1 SOL

Steps:
  1. Create a transaction sending 2 SOL to treasury
  2. Get the transaction signature
  3. Try to submit card with this signature
Expected Result:
✓ API returns 400 Bad Request
✓ Error message: "Invalid payment amount. Expected 1 SOL, received 2 SOL"
✓ Card is NOT published
✓ Extra SOL is NOT refunded (user error)
✓ Transaction rejected

Test Case 1.3: Payment of 0 SOL

Steps:
  1. Create a transaction sending 0 SOL
  2. Try to submit card
Expected Result:
✓ API returns 400 Bad Request
✓ Error message indicates invalid amount
✓ Card NOT published

Test Case 1.4: Payment Very Close to 1 SOL

Steps:
  1. Send 0.999999 SOL (just under 1 SOL)
  2. Try to submit card
Expected Result:
✓ API rejects payment
✓ Exact amount verification (1 SOL = 1,000,000,000 lamports)
✓ No rounding or approximation accepted

API Security

  • Validates required fields

  • CORS configured correctly

Backend Logic

  • Verification order correct
  • All rejections logged
  • Database transactions atomic
  • Error handling comprehensive

🛠️ Testing Tools and Commands

Using curl for API Testing

# Test with invalid amount
curl -X POST http://localhost:3000/api/cards/submit \
  -H "Content-Type: application/json" \
  -d '{
    "cardData": {...},
    "transactionSignature": "VALID_SIG_WITH_WRONG_AMOUNT",
    "walletAddress": "YOUR_WALLET"
  }'

# Test with duplicate signature
curl -X POST http://localhost:3000/api/cards/submit \
  -H "Content-Type: application/json" \
  -d '{
    "cardData": {...},
    "transactionSignature": "ALREADY_USED_SIGNATURE",
    "walletAddress": "YOUR_WALLET"
  }'

# Test with fake signature
curl -X POST http://localhost:3000/api/cards/submit \
  -H "Content-Type: application/json" \
  -d '{
    "cardData": {...},
    "transactionSignature": "FakeSignature123",
    "walletAddress": "YOUR_WALLET"
  }'

Check Backend Logs

# View PM2 logs
pm2 logs gorweld-backend

# View recent errors
pm2 logs gorweld-backend --err

# Tail logs in real-time
tail -f /path/to/backend/logs/error.log

Database Queries

# Check for duplicate signatures
sqlite3 backend/data/cards.db "SELECT signature, COUNT(*) FROM transactions GROUP BY signature HAVING COUNT(*) > 1;"

# View all transactions
sqlite3 backend/data/cards.db "SELECT * FROM transactions ORDER BY verified_at DESC LIMIT 10;"

# Check database schema
sqlite3 backend/data/cards.db ".schema transactions"
